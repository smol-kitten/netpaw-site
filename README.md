# NetPaw website

Static info + download + auto-wiki site for [NetPaw](https://github.com/smol-kitten/netpaw).
Served at https://netpaw.catboy.systems (planned).

## What it is

A static site generated by a single stdlib-Python script (`build.py`) at build time:

- **Home** — one-line pitch, four feature points, two screenshots (vendored from the NetPaw repo).
- **Download** — latest release from the GitHub Releases API: every asset with size and SHA-256
  (from the release's `SIGNATURES.md` / `NetPaw-<ver>.winget.json`, never typed by hand), plus older
  releases folded into a `<details>`.
- **Install** — three copy-able blocks:
  - **A** — winget via the self-hosted [catwinget](https://winget.goes.moe) source.
  - **B** — one-command MSI (PowerShell): downloads the latest MSI from GitHub, verifies its SHA-256,
    reports the Authenticode status, installs silently. Served at `/install.ps1` and shown expanded on
    the page so nobody has to pipe blind.
  - **C** — manual download + `Get-FileHash` + `Get-AuthenticodeSignature`.
- **Docs** — auto wiki: the NetPaw repo's README + user-facing `docs/*.md` rendered from GitHub at build
  time, with a sidebar and "edit on GitHub / source commit" per page.
- **Footer** — GitHub links (repo, releases, issues) and back.

## Security

- Static files only; no trackers, no cookies, no external fonts/CDNs.
- Strict CSP (no inline script/style — the only JS is an external copy-button file), HSTS,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `frame-ancestors 'none'`, `X-Frame-Options: DENY`.
  Set in `nginx.conf`.
- Downloads always point at GitHub Releases; this site never rehosts binaries.
- Light/dark via `prefers-color-scheme`.

## Rebuild

`.github/workflows/build.yml` rebuilds + pushes `ghcr.io/smol-kitten/netpaw-site` on:
- a schedule (hourly),
- `workflow_dispatch`,
- a `repository_dispatch` of type `netpaw-release`, which NetPaw's release job sends when the
  `RELEASE_DISPATCH_TOKEN` secret is set there (a fine-grained token with *Contents: write* on this repo).

After a push of the image this workflow sends the same `netpaw-release` dispatch to
`smol-kitten/netpaw-site-deploy` (secret `RELEASE_DISPATCH_TOKEN` here, *Contents: write* on the deploy
repo), so the live site follows a release within minutes instead of at the next hourly run. Without the
secrets both dispatch steps are skipped and the hourly schedules stay the fallback.

## Build locally

```sh
python3 build.py          # renders out/
docker build -t netpaw-site .
docker run -p 8080:8080 netpaw-site
```
